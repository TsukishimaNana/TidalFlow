# 三核心文档格式参考

新项目只需按此骨架填空，不要加多余章节。

---

## 1. AGENTS.md

**定位**：永久硬规则入口，新 agent 第二阅读顺位（第一是 CURRENT_SLICE）。

```markdown
# [[PROJECT_NAME]]

[[一句话描述]]

---

## 必读顺序

1. `CURRENT_SLICE.md`
2. `AGENTS.md`

按需读 `docs/` 下对应文件。

---

## 常用命令

| 命令 | 用途 |
|------|------|
| `[[COMMAND]]` | [[说明]] |

---

## 红线

- 禁止 [[X]]
- 禁止 [[Y]]
```

### 可选章节（按需选用）

| # | 章节 | 写什么 |
|---|------|--------|
| 1 | 必读顺序 | 新会话先读哪几个文件 |
| 2 | 任务前检查清单 | 开始做事前确认什么 |
| 3 | 常用命令 | 容易忘的命令，直接列 |
| 4 | Phase 规则 | 阶段命名和推进规则 |
| 5 | 审阅门禁 | 什么算完成、需要谁审 |
| 6 | 状态词汇 | DRAFT / REVIEWED / BLOCKED 等 |
| 7 | 来源安全 | 哪些数据源不能直接访问 |
| 8 | 路径/编码规则 | 文件路径和编码约定 |
| 9 | 红线 | 绝对禁止的行为 |
| 10 | 已知坑位 | 之前踩过的坑，症状 + 正确做法 |
| 11 | 文档维护 | 改完代码后怎么同步文档 |
| 12 | 回报要求 | 做完事怎么汇报 |
| 13 | 低成本执行 | 大文件读法、大文档写法、便宜模型配置 |

### 硬约束

- 控制在 **80-160 行**
- 不塞项目背景、完整规范、长日志（链到 docs/）
- 永久规则才放这，临时纠正放 CURRENT_SLICE

---

## 2. CURRENT_SLICE.md

**定位**：本轮快照，新 agent 第一阅读顺位。**每轮覆盖重写，不追加。**

```markdown
# Current Slice

用途：每轮可覆盖的最小接手面（~2KB）。
新会话只读本文件和 AGENTS.md；历史细节不足时读 Handoff 或 docs/phase-gate-log.md。
详细历史不要塞进本文件，放 gate log。

---

## CURRENT_PHASE

**[[Phase编号 + 状态]]**

## CURRENT_ACTION

[[一句话当前动作]]

## NEXT_TASK

1. [[下一步具体任务]]
2. [[第二项（可选）]]

## BLOCKERS

- [[阻塞项 或 无]]

## DO_NOT_REPEAT

- [[上一轮犯的错误]]
- [[最近被违反的规则]]

## READ_IF_*

- [[条件A]]: [[需要加载的 docs 或 skills]]
- [[条件B]]: [[需要加载的 docs 或 skills]]
```

### 各字段含义

| 字段 | 写什么 | 谁负责 |
|------|--------|--------|
| CURRENT_PHASE | 当前 Phase 编号 + 状态词 | 路由用 |
| CURRENT_ACTION | 一句话，当前在做什么 | 接手用 |
| NEXT_TASK | 1-2 条具体下一步 | 行动用 |
| BLOCKERS | 卡住的事，没有就写"无" | 防重复踩坑 |
| DO_NOT_REPEAT | 上一轮犯的错、最近违反的规则 | **只放临时纠正** |
| READ_IF_* | 条件加载表，什么场景加载什么文件 | 省上下文 |

### 硬约束

- **≤ 2-3KB / ≤ 50 行**
- **每轮覆盖**，不要追加历史
- 不要放 COMMON_COMMANDS（AGENTS.md 的事）
- 不要保留上一轮的 STATUS_FACT
- DO_NOT_REPEAT 只放临时纠正——永久规则放 AGENTS.md 红线

---

## 3. Handoff.md

**定位**：长期路线，低频更新。新 agent **最后才读**（正常流程不需要）。

```markdown
# Handoff

> 长期接手协议。当前具体下一步在 CURRENT_SLICE.md，本文件不追踪每轮任务。

## 项目路线

[[项目整体路线描述 — 2-4 句话]]

## 接手原则

- 先读 CURRENT_SLICE.md + AGENTS.md
- 按需读 docs/ 下对应文件
- 不确定时读 docs/roadmap.md 确认 Phase
```

### 硬约束

- **项目方向变了才改**——不是每轮更新
- **不写短期下一步**——写了就过时
- **不重复 CURRENT_SLICE 的内容**

---

## 三者分工一览

```
        改的频率      内容性质         agent 读的顺序
─────────────────────────────────────────────────
AGENTS   几乎不改     永久硬规则         第 2
SLICE    每轮覆盖     本轮快照           第 1 ⭐
Handoff  偶尔改      长期路线           最后（需要时）
```

新 agent 接手流程：

```
CURRENT_SLICE → AGENTS → （还不够？）→ Handoff → docs/*
```
